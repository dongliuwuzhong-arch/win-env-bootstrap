# 变更报告 · 2026-11-19 第五轮：P0/P1 落地 + 系统调优

> 范围：`docs/对标调研-20261119.md` 的 P0×3 + P1×3，外加用户点名的系统调优脚本。
> 验证基线：node 契约 117/117、Pester 21/21（含幂等收敛）、verify 硬缺口 0、smoke PASS、CI 双机型矩阵。
> 本轮动手前先看过 Boxstarter / 微软 hve-core / MCP 规范 / ruby CI 矩阵的做法，出处见对标调研。

## 一、挂起重启检测（对标 Boxstarter）

- **做了什么**：`bootstrap.ps1` 新增 `Test-PendingReboot`，探测三个挂起重启源
  （PendingFileRenameOperations / CBS RebootPending / WindowsUpdate RebootRequired），
  `-Check`/`-Apply` 在所有安装动作**之前**提示「有挂起重启，重启后重跑 -Apply」。
- **为什么**：winget 驱动/系统类包装到一半被打断，用户不知道要重跑，机器停在半残状态。
- **怎么验的**：Pester Mock 注册表探测，「三个源全亮报三条 / 干净报 0 条」两个方向都跑红过。

## 二、Pester 直测 bootstrap.ps1（对标微软 hve-core）

- **做了什么**：`tests-ps/` 三套件 21 例。用 PS parser 把函数定义（**含 C 式参数表**）
  抽进测试作用域，不执行脚本主体；PATH 读写包了一层 `Get-UserPath`/`Set-UserPath` 供 Mock。
- **钉住的历史 bug**：-split 标量陷阱（单条目 PATH 被拼接毁掉）、gapsLeft 跨段抵消、
  winget id 兜底、pending-reboot 判定、tweak 探针不猜状态。
- **CI**：新增 Pester 步骤。无头装 Pester 有俩坑已写进步骤注释：先引导 NuGet provider
  （否则 ShouldContinue 空引用），必须 `-ExecutionPolicy Bypass`（否则 AllSigned 拒载未签名测试）。
- **新坑入档**：PS 5.1 把无 BOM 的 UTF-8 当 ANSI 读，中文注释直接炸解析——测试文件必须带 BOM，
  且编辑动作会把 BOM 洗掉（本轮栽过两次）。锚点 `tests/ps-tests-contract.test.mjs` 钉死。

## 三、幂等收敛契约测试

- **做了什么**：假 winget/npm/python/frida 桩（只记日志不真装）+ 沙箱 DSH_HOME/WORKSPACE/USERPROFILE，
  起子进程连跑两次 `-Apply`，断言 run1→run2 **用户 PATH 与沙箱 home 文件清单零增量**。
- **为什么**：detect-then-fix 一直是口头承诺；社区共识是「convergent setup 该是基线行为」。
- **风险披露**：该测试在测试机上等于跑一次真 `-Apply`——用户 PATH 走真实注册表，
  可能被去重/补一次；备份写在测试沙箱里且**随测试清理，跑完没有回退件**，
  在意的话跑前自行留底（`reg export HKCU\Environment backup.reg`）。CI 上是全新 VM，无所谓。

## 四、CI 矩阵扩机型（对标 ruby/windows.yml）

- `windows-2022` + `windows-latest` 双跑，fail-fast: false。MAINTAINING 里
  「未覆盖」的账目收窄到 Windows 10 / ARM64 / 离线。

## 五、MCP 进度通知 + 取消（MCP 规范 2026-07-28，清留账 #11/#13）

- `verify.mjs --jsonl`：串行跑、每段完成吐一行 `{type:'segment'}`，末行 `{type:'done', ...}` 带全量结果。
- `server.mjs`：`env_status` 带 `_meta.progressToken` 时走流式，逐段发 `notifications/progress`；
  支持 `notifications/cancelled` 掐断在途请求（应答 `-32800 request cancelled`）。
- M 段最长 240s 无反馈的问题就此了结；SIGTERM 优雅退出仍留账（取消已覆盖手动掐断场景）。

## 六、换机清单导出 `-ExportInventory`（对标 winget export/import）

- `winget export`（微软官方换机格式，单出一份）+ 两套 python 的 `pip list --format=json`
  + `npm -g list`，合落 `~/.dsh/inventory-时间戳.json`。换机后对单查漏。

## 七、系统调优 `tweaks.ps1`（用户点名要的，压过调研里的「不抄」判断）

- 5 个 opt-in 项：longpaths / power-highperf / gamebar-off / defender-exclusions / hiberfil-off。
  清单在 `manifest.tweaks`（单一配置源），`-List` 纯探测、`-Apply`/`-Revert` 逐项、
  `all` 批量；admin 项在非管理员终端直接 FAIL 不硬写；探不到真实状态报 `unknown` 不猜
  （本机 Defender 被第三方接管就是这么报的）。
- **与环境补齐严格分家**：bootstrap 不碰 OS 设置，tweaks 不碰工具链，两个入口互不隐含。

## 八、三子代理二验与处置（34 条发现全数落地）

三个独立子代理（判据审查 / 文档一致性 / 对抗实测）并行复核本轮，共 34 条发现，全部处置：

- **判据审查 14 条**：最重的两条——CI 的 Pester 步骤判据读的是环境残留
  （`Invoke-Pester` 是 cmdlet 不设 `$LASTEXITCODE`，红绿都会判反）→ 改读 `-PassThru` 的
  `FailedCount`；同批取消确定性丢失 → 读循环不 await + slot 先于 spawn 注册，并挖到
  真根因（无 progressToken 的请求走 spawnSync 卡死事件循环，根本不可取消）→ env_status
  一律异步。其余：hiberfil 探针对内核独占文件恒假（走注册表真值）、超时伪装成取消（自管
  计时 + 三态分离）、取消只杀单进程（taskkill /T 杀树）、崩溃段进度行装全绿、total 口径、
  清单 JSON 带 BOM、pip 残差混进库存、tweaks 退出码、gamebar 半写状态、空数组误报挂起、
  收敛测试沙箱指错导致备份落 Temp。
- **对抗实测 5 条**：空 `--only` 静默全量（改 64）、同批取消（同上）、进度 total、
  错误透传、tweaks 打错字退码。另用**变异测试**证明断言真咬合：改坏判据测试必红
  （pending-reboot 少一源、-split 陷阱复活两处都实测转红）。
- **文档一致性 10 条**：defender 排除范围声明失实（补代码：工作区 + DSH 目录双路径）、
  段行数/坑数/耗时口径/CI 描述/smoke 职责/清单落点/备份披露等全部对齐实况。
- **纪律自伤两条也入了账**：编辑动作往 ASCII 文件塞中文注释炸解析（tweaks.ps1 实炸、
  bootstrap.ps1/smoke.ps1 潜伏）——全部英文化，新增 `scripts/*.ps1` 纯 ASCII 锚点测试；
  编辑动作洗掉 BOM 的坑已有锚点钉着。
