# 对标调研：社区里可借鉴的东西（2026-11-19）

> 面向 dsh-env-bootstrap 的外部对标：官方生态 + 社区同类项目。只记「能抄什么、别抄什么」，来源链接附在各条。
> 结论落点：新条目进 [维护日志](维护日志.md)，动手前先过 MAINTAINING 的三条铁律。

## 值得抄（按 ROI 排序）

### 1. 断电续跑与 pending-reboot 检测（Boxstarter 模式）——先做
Boxstarter 的核心就是「包装安装脚本，重启后继续」（chocolatey-community/boxstarter）。
我们靠幂等重跑兜底，但没检测「系统有挂起重启」——winget 装驱动类包会要求重启，
中途重启后用户不知道该重跑。做法：I/O 段加 `Test-PendingReboot` 类检测（注册表
PendingFileRenameOperations / CBS RebootPending），报「有挂起重启，建议重启后重跑 -Apply」；
可选加分项：RunOnce 自动续跑。
来源：https://github.com/chocolatey-community/boxstarter

### 2. Pester 直测 bootstrap.ps1 函数——先做
现在 bootstrap 只有 regex 锚点测试，判据级 bug（-split 标量、IsNullOrEmpty 失效）
全是靠人肉抓的。微软 hve-core 仓库的做法：Pester 套件 + `Invoke-PesterTests.ps1`
统一入口 + CI 退出码/NUnit 输出 + 覆盖率摘要 JSON。把 Say / Install-Pkg /
Remove-PathDuplicates / Test-PathEntry / Get-CmdVersion 剥出来做 Pester 5.x 单测，
CI 加一步。锚点测试留着，两者互补。
来源：https://github.com/microsoft/hve-core（scripts/tests/README.md）

### 3. 幂等收敛契约测试——先做
社区共识：「convergent setup should be the baseline behavior, not a best-effort
side effect」（ladislas/dotfiles#40）。我们口头承诺 detect-then-fix、二次运行零改动，
但没有测试钉它。做法：假 winget/pip 桩（PATH 里放假 exe 计数调用）跑两遍 -Apply，
断言第二遍「零安装动作、零新增 PATH、零写文件」。
来源：https://github.com/ladislas/dotfiles/issues/40

### 4. CI 矩阵扩机型——跟上
ruby 的 windows.yml 按 os 2019/2022/arm64 矩阵跑（fail-fast: false）。
MAINTAINING 里「Windows 10 / ARM64 未覆盖」这笔账可以直接清一部分：
matrix 加 windows-2022（+ windows-latest），ARM64 视 runner 可用性。
来源：https://github.com/ruby/ruby/.github/workflows/windows.yml

### 5. MCP 补 progress + cancellation——跟上（清留账 #11/#13）
MCP 规范有现成的 `notifications/cancelled` 与 progress 通知模式
（modelcontextprotocol.io 规范 2026-07-28）。env_status 跑 M 段最长 240s 无进度的
问题，按规范发进度通知即可；顺手把 cancelled 支持补上，客户端可掐长任务。
来源：https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation

### 6. 换机清单导出（winget export/import）——顺手
winget 自带 `winget export -o packages.json` / `winget import`（微软官方推的
换机方案）。加一个 `-ExportInventory`：winget export + pip list ×2 + npm -g list
落一份 json，P 段或新段检查「清单在不在」。换机完整性从「人肉记」变「有单可查」。
来源：https://techcommunity.microsoft.com/t5/itops-talk-blog/bc-p/2531651

### 7. winget configure（DSC）作为安装后端备胎——中期
微软官方方向：YAML 声明 + `winget configure` 一键收敛
（learn.microsoft.com/windows/package-manager/configuration；实例见
microsoft/WindowsDeveloperConfig）。从 manifest.tools 生成 configuration.winget，
公开工具那层可以交给官方引擎。不替代我们（G2 修复、中文报告、PATH 修缮它干不了），
但能让「装工具」这一半跟官方生态对齐，新机用户少装东西时更顺。

## 不抄

| 项目/方向 | 为什么 |
|---|---|
| WinUtil / Sophia 这类系统调优脚本 | 方向是 tweaks，改动面大，违背「不动宿主数据、系统」的底线 |
| chezmoi 式 dotfiles 管理 | 工作区已有同步方式，引第二个真相源必打架 |
| Boxstarter 远程部署 / Hyper-V 集成 | 单机场景用不上 |
| Chocolatey 双包管理器后端 | winget 已够，双后端徒增测试矩阵 |

## 社区共识（印证我们已有的）

- 幂等可重跑是 setup 脚本的底线（chezmoi: "run it once or a hundred times, and the
  result is always the same"）——我们 detect-then-fix 同款，缺的只是测试（见 3）。
- doctor 三态语义（ok / warning / error，chezmoi doctor）——verify 的 0/1/2 已同款。
- 装完必须实测命令可解析（我们的 Install-Pkg 复测）——比只信退出码的脚本严，保持。
