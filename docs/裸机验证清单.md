# 裸机验证清单（V1）——把「开箱即用」从承诺变实证

> 来源：2026-11-19 第三方审计 P0-1。**唯一没有代码解的项**：需要一台干净 VM + 一次人工跑批。
> 跑完把日志归档到本目录（`裸机验证-YYYYMMDD/`），并在维护日志记一行。
> 顺手把 V5（7-Zip 探针）/ V6（非管理员）并进同一次测试，一鱼三吃。

## 准备

- 干净 Windows 11 VM（Hyper-V / VMware，**先拍快照**）
- 旧机的两件行李：`~/.dsh`（含 `profiles\desktop\node_modules`）、工作区目录

## 步骤（全程 Tee-Object 留日志）

```powershell
# 1) 官方安装器装 DSH 本体（阶段一）
# 2) 从旧机整目录拷 ~/.dsh 与工作区
# 3) [Environment]::SetEnvironmentVariable('DSH_WORKSPACE','D:\你的工作区','User')

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -Check            # 记录缺口清单，核对 00 段引导是否说人话
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -Apply 2>&1 | Tee-Object apply1.log

# 4) 重开 shell（PATH 生效）后：
node scripts\verify.mjs --json | Out-File verify1.json    # 期望硬缺口 0

# 5) 幂等复跑：
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -Apply 2>&1 | Tee-Object apply2.log
reg export HKCU\Environment compare.reg                   # 与 run1 后比对 PATH 零增量
#   ~/.dsh 下 path-backup/path-dedup 不再新增
```

## 检查点（跑完逐条打勾）

- [ ] 00 段把「该人工做的」和「脚本做的」分得清
- [ ] 自动装链路：winget/pip/npm 全部装上且复测可解析（无「装了找不到」残留）
- [ ] F 段 pip 失败时（若有）报错带真实原因，不是一句 install failed
- [ ] verify --json 硬缺口 0；M 段有「等待」提示而不是静默
- [ ] 二次 -Apply：PATH 零增量、备份文件不新增、无重复安装告警堆积
- [ ] 【并测 V6】标准用户终端跑一次 -Apply：提示是否够用、user-scope 是否被尝试
