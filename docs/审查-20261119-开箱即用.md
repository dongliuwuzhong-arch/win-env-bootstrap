## 一、严重问题（3 项）

### 严重 #1：`$wsPath` 在赋值前使用 —— puppeteer 自动安装块是死代码

- **问题**：`bootstrap.ps1:466` 的 `$pptrDir = Join-Path $wsPath '_tools\browser'` 在 **498–504 行 `$wsPath` 赋值之前**执行。此时 `$wsPath` 为 `$null`，`Join-Path $null` 抛参数绑定异常（`$ErrorActionPreference='Continue'` 下非终止），整个 if/elseif 链静默跳过。**"安装 puppeteer"这条 P0 修复从未生效过**。另外 puppeteer 有两块重复逻辑（465–481 块死、505–507 块只报不装）。
- **影响范围**：`-Apply` 在含 `_tools\browser` 的工作区上也装不了 puppeteer；fetch-render.mjs 持续不可用；stderr 里刷参数绑定错误。
- **触发条件**：任何机器（该块恒不执行）。已实测确认 `Join-Path $null` 抛「无法将参数绑定到参数"Path"」。
- **修复方向**：把 `$wsPath` 解析块（498–504 行）整体上移到 C 段之前；合并重复的 puppeteer 两块为一块（检测→安装→复测）；给该块加 `if ($wsPath)` 守卫。
- **验证步骤**：
  ```powershell
  # 1) 缺陷确认：定位使用点在赋值点之前
  Select-String -Path scripts\bootstrap.ps1 -Pattern 'wsPath' | Select LineNumber, Line
  # 期望修复后：赋值行号 < 所有使用行号
  # 2) 功能验证：在有 _tools\browser\package.json 但无 node_modules 的工作区跑
  powershell -NoProfile -ExecutionPolicy Bypass -File scripts\bootstrap.ps1 -Apply
  # 期望：出现 "installing puppeteer in _tools\browser ..."，结束时该目录下有 node_modules\puppeteer
  ```

### 严重 #2："9 个只查不装补齐"未兑现 —— frida / 微信 4 包 / DSH python 缺包仍无安装动作

- **问题**：`c761ed2` 提交宣称"补齐 9 个只查不装的依赖"，实测安装动作覆盖：rg ✅、jq ✅、exiftool ✅、dotnet ✅、magick ✅、ffprobe（随 ffmpeg 复测）✅、**puppeteer ❌（见 #1）**、**frida ❌（bootstrap.ps1:511–513 仍只 warn，manifest 声明的 `pip: frida-tools` 无人消费）**、**wechat 4 包（cryptodome/zstandard/pysilk）与 DSH 自带 python 缺包 ❌（无任何安装动作）**。
- **影响范围**：换新机后 wechat-history（取证）与 DSH python 工具链依旧不可用，只能人工逐个 pip install。
- **触发条件**：全新机器 `-Apply` 后跑 verify，E/F 段仍报缺。
- **修复方向**：bootstrap 补三类动作——`pip install frida frida-tools`（仿 F 段写法）、按解释器分别补装 wechat 4 包与 DSH python 核心包（`f-python-packages.js` 已区分两套解释器，安装动作照此对齐）；消费 manifest 里的 `pip` 字段。
- **验证步骤**：
  ```powershell
  # 卸载或在干净环境确认缺失后：
  powershell -NoProfile -ExecutionPolicy Bypass -File scripts\bootstrap.ps1 -Apply
  node scripts\verify.mjs --only=E,F
  # 期望：frida 转绿；python:frida/cryptodome/zstandard/pysilk 转绿或至少 info→ok
  ```

### 严重 #3：工作区解析双脚本不一致 —— 同一台机器结论相反

- **问题**：
  - `bootstrap.ps1:498–504`：`-Workspace` 参数 > `DSH_WORKSPACE` 环境变量 > manifest.default > **内置兜底 `C:\DSH空间`**。
  - `scripts/lib/paths.js:55–58`（verify/MCP 用）：manifest.default（公开版为空）> `DSH_WORKSPACE` > **兜底空字符串**。
  - 于是一台工作区在 `C:\DSH空间`、但没设 `DSH_WORKSPACE` 的机器：bootstrap 报 `[OK] workspace: C:\DSH空间`，verify 报 `✗ 工作区不存在: `（空路径）。00 段的 workspace 判定（`Boolean(ctx.WS) && ...`）同样误报"拷工作区"未完成。
  - 附带：优先级顺序也不同（verify 把 manifest.default 排在环境变量前，bootstrap 相反）。
- **影响范围**：所有未显式设 `DSH_WORKSPACE` 的机器（含最典型的新机）；agent 走 MCP 拿到的 `env_status` 与人工跑 bootstrap 的结论互相矛盾，破坏"实时反馈"的可信度。
- **触发条件**：`manifest.workspace.default` 为空 + 未设 `DSH_WORKSPACE`。
- **修复方向**：统一解析函数（建议在 `paths.js` 导出、bootstrap 端复刻同一顺序），并规定同一优先级：参数 > 环境变量 > manifest > 兜底；兜底值两边一致（要么都空并显式提示"未配置工作区"，要么都内置 `C:\DSH空间`）；空路径时输出应为「工作区未配置（设 DSH_WORKSPACE 或改 manifest）」而非「不存在: 」。
- **验证步骤**：
  ```bash
  # 不设 DSH_WORKSPACE 分别跑两个脚本，对比工作区结论
  node scripts/verify.mjs --only=00,H
  # 与
  # powershell ... bootstrap.ps1 -Check
  # 期望：两边对工作区的有/无结论一致，且都不出现"不存在: "（空路径）
  DSH_WORKSPACE="C:/DSH空间" node scripts/verify.mjs --only=00,H   # 设了变量后都应转绿
  ```

## 二、一般问题（6 项）

### 一般 #4：MCP `tool_resolve` 不查 `manifest.tools[].pathDirs` —— 最核心场景误报

- **问题**：`scripts/mcp/server.mjs:106` 只用 `where probeCmd` 找 PATH；7-Zip 等工具 manifest 里声明了 `pathDirs`（安装目录候选），但 resolve 不回退查这些目录。于是**"装了但不在 PATH"（本工具存在的头号理由）在 MCP 侧被报成 `resolved: false`**。另外 `inPath` 字段与 `resolved` 完全同义（都是 `Boolean(path)`），无法区分"未安装"与"已安装未入 PATH"。
- **影响**：agent 通过 MCP 判断 7-Zip/ImageMagick 等状态时得到错误结论，可能触发不必要的安装。
- **触发**：工具已装但目录未入 PATH（7-Zip 经典坑）。
- **修复**：resolve 增加 pathDirs/exeName 回退探测；`inPath` 改为「where 命中」，`resolved` 改为「PATH 命中或 pathDirs 命中」，并新增 `installedNotInPath` 状态。
- **验证**：临时把 7-Zip 从 PATH 移除后调 `tool_resolve {name:"7z"}`，期望返回 `resolved:true, inPath:false`（当前会返回 `resolved:false`）。

### 一般 #5：MCP `tool_resolve` 把用户输入传入 `cmd /c`

- **问题**：`server.mjs:111` `spawnSync('cmd', ['/c', probeCmd, ...])` 中 `probeCmd` 可为任意用户输入（不在 manifest 时直接用 `name`）。当前**被 `where` 的存在性检查意外挡住**（Windows 文件名不含 `&` 等元字符），但注释声称"不用 shell+args"与实际用 `cmd /c` 矛盾，属"靠运气的安全"。
- **影响**：MCP 服务被恶意/异常输入利用的潜在面；审计时会被判为注入风险点。
- **触发**：构造特殊 name（当前不可利用，但换实现或 Windows 行为变化后可能可利用）。
- **修复**：name 白名单校验（`/^[A-Za-z0-9._-]+$/`）+ 仅允许 manifest 内工具或 `where` 解析出的绝对路径；或改用 `spawnSync(exePath, args)` 直接执行解析出的 exe。

### 一般 #6：verify `--json` 出错时 MCP 把错误当成功结果返回

- **问题**：`verify.mjs --json --only=ZZ` 时错误写 stderr、退出码 64、stdout 非 JSON。`server.mjs:37–41` 捕获后返回 `{error: ...}` 包在 `result.content` 里，**未设置 `isError: true`**。agent 按 MCP 规范会把这当成成功调用。
- **影响**：agent 对坏参数无感知，可能把 error 对象当体检结果解读。
- **修复**：`callTool` 支持返回错误标记（`isError: true`）；未知段名时 MCP 侧先校验 `only` 字符集。
- **验证**：`tools/call env_status {only:"ZZ"}`，期望返回 `isError: true`（当前无此标记）。

### 一般 #7：文档漂移 —— 已可装的工具仍写"只查不装"

- **问题**：`README.md:43,91` 与 `SKILL.md:144–145` 仍写「ImageMagick、rg、jq……只查不装/不装」，但本轮代码已可自动装。反向的不一致同样存在（frida 等真不装的没在文档中说清"需要人工"）。
- **影响**：用户据文档预期"装不了"而人工去装，或以为"能装"结果落空。
- **修复**：文档安装矩阵与 `manifest.tools` + bootstrap 安装动作做一致性锚点测试（一条测试 grep README 与 Install-Pkg 清单）。

### 一般 #8：bootstrap 不输出 00 人工前置清单

- **问题**：00 段只存在于 verify.mjs；新机用户**先跑 bootstrap**（README 的推荐入口）时看到的是一片红（DSH host missing / .dsh missing / workspace missing…），却没有"这 4 项是阶段一人工前置、不是本技能能修的"引导。00 段的设计意图（agent 跑完一次知道差哪几步）对 bootstrap 用户反而缺失。
- **影响**：开箱第一印象差；新机用户难以区分"该我做的"与"该脚本做的"。
- **修复**：bootstrap 开头或结尾输出 prerequisites 清单（读 manifest.prerequisites，复刻 00 段的三态）。
- **验证**：在缺 `~/.dsh` 的机器跑 `bootstrap.ps1 -Check`，期望输出与 verify 00 段等价的人工前置清单。

### 一般 #9：00 段文案重复与判定盲区

- **问题**：`00-prerequisites.js:35` 拼接 `p.title + '（可选）'`，而 manifest 的 title 已含"（可选）"，输出变成「设 DSH_WORKSPACE（可选）（可选）」。另外 `env` 状态只认 `process.env.DSH_WORKSPACE`，不认 manifest.default 或 `-Workspace` 参数——通过后两者配置工作区时会误报未设置。
- **修复**：去掉拼接的"（可选）"；env 判定改为「WS 已解析且非默认」。

## 三、建议（6 项）

| # | 事项 | 说明 |
|---|---|---|
| 10 | `tool_resolve` 对 `versionArgs: []` 的工具（7z）会把 `cmd /c 7z` 的帮助首行当版本号 | 应跳过版本探测或用专用参数 |
| 11 | verify / MCP 批量返回，M 段 selfcheck 最长 240s 无进度 | 长耗时段输出开始/结束时间戳，或 verify 支持流式逐段输出 |
| 12 | 无 `-DryRun` 计划预览 | `-Apply` 前输出"将装 X / 将改 Y / 人工 Z"，与实际执行可比对 |
| 13 | MCP 缺 `notifications/cancelled`、SIGTERM 优雅退出、`isError` 规范 | 补协议完整性 |
| 14 | `00` 段与 `H` 段对工作区的判定口径重复（都查 skills/persona） | 合并或让 00 只查"存在"、H 查"内容完整" |
| 15 | 幂等性已较好（detect-then-fix、PATH 备份、junction 跳过），但 winget 重装时 `-1978335212` 记为 warn | 重复 `-Apply` 会产生一堆"already installed"警告，建议归为 ok/info |
