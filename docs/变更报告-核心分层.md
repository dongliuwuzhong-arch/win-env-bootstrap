# 变更报告 · core / dsh 模块分层（2026-11-19）

> 落地二审报告第五节架构方案。目标：非 DSH 用户一条命令得到可用的通用换机体检+装机体验，
> DSH 用户感知不变。

## 结构

- **清单源**：`manifest.modules` + `categories[].module`（00/G/G2/H/L/M = dsh，其余 core）+ `tools[].module`。
- **判定源**：`paths.js resolveModules()`——显式 profile > `DSH_MODULES` 环境变量 > 自动探测（DSH_ROOT 或 ~/.dsh 在 → 双开）。
- **verify**：`--profile=core|dsh`；无 `--only` 时按 module 过滤段并打一行跳过提示；`--only` 点名优先于过滤。
- **bootstrap**：`-Profile Core|Dsh`；段级闸（0/G/G2/H/L + F 的 DSH 段），坏 profile 值警告后回落自动。
- **MCP**：`env_status` 支持 `profile` 参数透传。
- **项级门**：混合段里的 DSH 项（F 的 dshBundled、P 的 WE_DATA/AGENTS/vbs、N 的 soul/ChatTrace/TTS、a 的自带 pnpm 探测）走 `ctx.hasDsh`，core 档不出现也文案中性。
